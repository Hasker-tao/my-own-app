# 个人工作生活管理 App 产品需求文档

## 文档信息

- 文档状态：第一版需求已确认
- 产品形态：仅供个人使用的本地 Web App
- 运行环境：当前电脑的桌面浏览器
- 数据方式：本地独立数据文件，支持备份与恢复
- 本版范围：第一版（MVP）

## 1. 产品目标和使用场景

### 1.1 产品目标

本产品是一套只供用户本人使用的工作生活管理工具。它把每天的计划、自媒体创作、开发工作、咨询工作、健身、饮食和游戏娱乐集中在一个本地 App 中，减少信息分散在多个文档、备忘录和任务工具中的情况。

产品需要实现以下目标：

1. 用户打开首页后，可以快速了解今天要做什么、哪些事情需要关注，以及各模块当前最重要的状态。
2. 每个模块按照自身场景管理专业数据和操作，而不是复用一套改名后的任务列表。
3. 今日计划只负责安排“今天何时执行什么”，业务详情仍由对应模块管理，避免重复录入。
4. 所有数据保存在当前电脑的独立文件中。刷新页面、关闭浏览器、关闭本地 App 服务或重启电脑后，数据不得丢失。
5. 用户可以查看数据文件位置，手动或自动备份，并从备份中恢复。

### 1.2 主要使用场景

- 每天开始工作前，在首页查看今日安排和需要关注的事项。
- 随手记录一个临时想法，并在需要时把它转换为今日事项或某个模块的正式记录。
- 在今日计划中安排来自自媒体、开发、咨询、健身、饮食或娱乐模块的行动。
- 在各业务模块中记录专业信息，例如内容制作阶段、开发 Bug、客户跟进、训练组数或饮食摄入。
- 每天结束时查看完成情况并填写简短复盘。
- 定期创建备份；出现误删、文件损坏或需要回退时恢复数据。

### 1.3 使用边界

- 仅供单个用户在当前电脑上使用。
- 不需要注册、登录或多用户权限。
- 不依赖互联网、云数据库或第三方在线服务完成核心功能。
- 不需要公网部署、局域网共享或手机端适配。
- 本地服务只能从当前电脑访问。

## 2. 整体页面框架和导航结构

### 2.1 整体框架

App 采用固定左侧导航、顶部工具栏、中央内容区和按需出现的详情侧边栏。

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 个人工作台    │ 日期 / 全局搜索 / 保存状态 / 快速新增 / 备份  │
│              ├──────────────────────────────────────────────┤
│ 左侧导航      │                                              │
│              │               当前页面内容                   │
│              │                                              │
│              │                              ┌─────────────┐ │
│              │                              │ 详情侧边栏  │ │
│              │                              │ 编辑与记录  │ │
│              │                              └─────────────┘ │
└──────────────┴──────────────────────────────────────────────┘
```

页面设计以桌面浏览器为主。浏览器窗口变窄时，左侧导航可以收起，但第一版不需要专门设计手机布局。

### 2.2 左侧导航

导航分为四组：

1. 日常
   - 首页总览
   - 今日计划
2. 工作
   - 自媒体
   - 开发工作
   - 咨询工作
3. 生活
   - 健身计划
   - 饮食计划
   - 游戏娱乐
4. 系统
   - 数据与设置

### 2.3 顶部工具栏

顶部工具栏在主要页面保持一致，包含：

- 当前日期。
- 全局搜索入口。
- 快速新增入口。
- 当前数据保存状态，例如“保存中”“已保存”或“保存失败”。
- 最近一次备份状态。

### 2.4 通用页面和交互结构

- 简单新增或编辑使用小型弹窗或右侧详情栏。
- 需要集中处理较多信息时，进入完整详情页。
- 日常编辑默认自动保存，同时在顶部提供全局“手动保存”按钮，用于立即提交自动保存草稿并将已提交数据写入本地数据文件。
- 删除内容先进入回收站；永久删除需要再次确认。
- 重要操作完成后提供明确反馈；可安全撤销的操作应提供撤销入口。
- 全局搜索结果按模块分类，并可以直接打开对应记录。
- 支持通过 `Ctrl/Command + K` 打开搜索与快捷操作。
- 拖动只用于时间安排和流程状态等自然场景，同时必须提供点击菜单作为替代操作。
- 所有重要页面都需要处理正常、空数据、加载中和出错状态。

## 3. 首页的内容结构

首页是当天的行动和状态总览，不是所有模块数据的完整集合。

### 3.1 页面布局

```text
┌──────────────────────────────────┬──────────────────────┐
│ 今天的日期、完成进度和简短状态    │ 快速备忘             │
├──────────────────────────────────┤ 随手输入、自动保存    │
│ 今日时间线                        ├──────────────────────┤
│ 已安排具体时间的事项              │ 需要关注             │
├──────────────────────────────────┤ 到期、跟进、异常提醒  │
│ 尚未安排时间的今日事项            ├──────────────────────┤
│                                  │ 各模块重要摘要       │
└──────────────────────────────────┴──────────────────────┘
```

### 3.2 首页内容

1. 今日概况
   - 当前日期。
   - 今日已完成数量和总数量。
   - 今日计划完成进度。
   - 预计已安排时间。
2. 今日时间线
   - 展示已经设置具体时间的今日事项。
   - 支持打开详情、调整时间和标记完成。
3. 待安排事项
   - 展示属于今天、但尚未设置具体时间的事项。
4. 快速备忘
   - 输入内容后自动保存。
   - 可以归档，也可以转换成今日事项或某个模块的正式记录。
5. 需要关注
   - 即将到期或已经到期的事项。
   - 需要跟进的咨询项目。
   - 今天计划但尚未完成的训练等重要提醒。
6. 模块摘要
   - 自媒体：近期待发布或制作中的重点内容。
   - 开发工作：当前项目、临近里程碑和高优先级问题。
   - 咨询工作：近期会议、交付和待跟进客户。
   - 健身计划：今日训练和近期训练情况。
   - 饮食计划：下一餐和今日营养目标完成情况。
   - 游戏娱乐：当前游戏和计划的娱乐时间。

首页摘要必须可以点击，并进入对应模块或直接打开对应记录。

## 4. 各模块用途、必要数据和操作

### 4.1 今日计划

#### 用途

用于安排某一天要执行的事项、时间和优先级，并回顾当天完成情况。它可以关联其他模块中的记录，但不复制对应模块的业务详情。

#### 第一版最必要的数据

- 标题。
- 所属日期。
- 开始时间，可为空。
- 预计时长，可为空。
- 优先级。
- 状态：未开始、进行中、已完成、已取消或已延期。
- 来源模块和来源记录，可为空。
- 简短备注。
- 完成时间，可为空。
- 当日复盘文本。

#### 第一版最必要的操作

- 新增、编辑和删除计划事项。
- 设置日期、时间、时长和优先级。
- 标记开始、完成或取消。
- 延期到明天或指定日期。
- 在今日时间线中调整时间。
- 关联或打开来源模块记录。
- 查看今日、本周和历史记录。
- 填写当天简短复盘。

### 4.2 自媒体

#### 用途

管理从内容灵感到发布及效果记录的完整创作流程。

#### 第一版最必要的数据

- 内容标题。
- 发布平台。
- 内容形式。
- 制作阶段：灵感、待策划、制作中、待发布或已发布。
- 计划发布日期，可为空。
- 实际发布日期，可为空。
- 文案或内容笔记。
- 素材在本地电脑中的位置，可为空。
- 发布链接，可为空。
- 播放或阅读量、点赞数、评论数，可为空。

#### 第一版最必要的操作

- 快速记录灵感。
- 新增和编辑内容。
- 通过看板拖动或菜单改变制作阶段。
- 安排计划发布日期。
- 标记内容已发布并保存发布链接。
- 手动记录基础表现数据。
- 把内容的下一步行动加入今日计划。
- 归档不再需要显示的内容。

### 4.3 开发工作

#### 用途

管理个人开发项目、里程碑、功能需求、Bug、技术问题和开发日志。

#### 第一版最必要的数据

- 项目名称、说明和状态。
- 本地项目目录，可为空。
- 代码仓库或文档链接，可为空。
- 里程碑名称、目标日期和状态。
- 工作项标题、类型、优先级、状态和所属里程碑。
- 工作项类型：功能、需求、Bug 或技术问题。
- 开发日志的日期和内容。

#### 第一版最必要的操作

- 新增、编辑和归档项目。
- 新增和管理里程碑。
- 新增、编辑、分类和完成工作项。
- 按类型、状态和优先级筛选工作项。
- 记录连续的开发日志。
- 复制或尝试打开本地项目目录。
- 把工作项加入今日计划。

### 4.4 咨询工作

#### 用途

围绕客户、咨询项目、沟通记录、交付和后续跟进管理咨询工作。

#### 第一版最必要的数据

- 客户名称和基础备注。
- 咨询项目名称、客户、当前需求和状态。
- 沟通或会议的时间、形式和记录。
- 交付物名称、截止日期和状态。
- 下次跟进时间和跟进内容。
- 咨询时长。
- 费用金额和是否结算，可为空。

#### 第一版最必要的操作

- 新增、编辑和归档客户及咨询项目。
- 记录一次沟通或会议。
- 新增、完成和延期交付物。
- 设置并完成客户跟进。
- 记录咨询时长和简单费用信息。
- 把会议、交付或跟进加入今日计划。
- 在首页显示临近交付和长期未跟进提醒。

### 4.5 健身计划

#### 用途

制定训练计划，快速记录实际训练内容，并查看身体和训练表现的变化。

#### 第一版最必要的数据

- 训练模板名称和计划星期。
- 动作名称、目标组数、次数、重量和休息时间。
- 实际训练日期和完成状态。
- 每组实际次数和重量。
- 训练感受或备注。
- 体重、围度等身体数据，可按需填写。

#### 第一版最必要的操作

- 新增和编辑训练模板。
- 把训练安排到某一天。
- 从模板开始一次训练。
- 快速记录每组完成情况、次数和重量。
- 查看上一次相同动作的数据。
- 完成训练并生成训练摘要。
- 记录身体数据。
- 查看训练次数、训练重量和身体数据的简单趋势。

### 4.6 饮食计划

#### 用途

安排每日餐食、记录实际摄入，并查看当天营养目标完成情况。

#### 第一版最必要的数据

- 每日热量和蛋白质目标；其他营养目标可为空。
- 餐次：早餐、午餐、晚餐或加餐。
- 餐食名称和日期。
- 计划食物与实际食物。
- 食物名称、份量、热量和蛋白质；未掌握的数据允许为空。
- 常用食物记录。

#### 第一版最必要的操作

- 设置每日营养目标。
- 安排今天或一周的餐食。
- 记录实际吃过的食物和份量。
- 从常用食物快速添加。
- 复制昨天或指定日期的餐食。
- 自动汇总当天已填写的营养数据。
- 区分计划餐食与实际摄入。

### 4.7 游戏娱乐

#### 用途

管理游戏清单、游玩进度、个人笔记和娱乐时间，同时避免使用工作式的逾期压力。

#### 第一版最必要的数据

- 游戏或娱乐项目名称。
- 平台或活动类型。
- 状态：想玩、正在进行、暂停或已完成。
- 当前进度。
- 下一次目标。
- 攻略或个人笔记。
- 单次游玩开始时间、结束时间和时长。
- 个人评分和完成日期，可为空。

#### 第一版最必要的操作

- 新增和编辑游戏或娱乐项目。
- 改变进行状态。
- 开始和结束一次游玩记录。
- 更新进度和下一次目标。
- 记录个人笔记和评分。
- 把计划的娱乐时间加入今日计划。
- 查看累计游玩时间。

### 4.8 数据与设置

#### 用途

查看本地数据状态，执行备份、恢复、导出和基础偏好设置。

#### 第一版最必要的数据

- 当前数据文件位置、大小和最近修改时间。
- 备份文件位置、创建时间、大小和用户备注。
- 自动备份保留状态。
- 主题、每周起始日、日期时间格式等使用偏好。
- 首页需要显示的模块摘要。

#### 第一版最必要的操作

- 查看并打开数据目录。
- 手动创建完整备份。
- 查看自动和手动备份列表。
- 为重要备份命名或标记保留。
- 从指定备份恢复。
- 导出常见格式的数据。
- 修改并保存使用偏好。
- 查看和清理回收站。

## 5. 首页、今日计划和各模块之间的关系

### 5.1 数据关系原则

```text
各业务模块中的专业记录
          │
          │ 产生或关联“下一步行动”
          ▼
      今日计划负责安排执行
          │
          │ 汇总当天状态
          ▼
       首页负责展示重点
```

1. 各业务模块是专业数据的唯一来源。例如开发工作项的类型、里程碑和技术说明只保存在开发模块。
2. 今日计划保存执行安排，并通过关联关系指向来源记录，不复制完整业务数据。
3. 从今日计划打开关联事项时，应进入对应模块或打开对应记录详情。
4. 今日计划完成一个关联行动后，来源模块应立即显示相关状态变化；具体哪些业务状态自动变化，由对应操作明确决定，不能静默修改大量数据。
5. 首页从今日计划和各模块读取摘要，不单独维护另一份相同数据。
6. 首页摘要发生变化后应及时更新；点击摘要可以回到数据来源。
7. 快速备忘最初是独立记录，转换成其他类型后，需要保留来源或明确标记已经转换，避免重复处理。

### 5.2 首页摘要原则

- 只展示需要今天关注或近期处理的信息。
- 不为了填满页面而展示无意义统计数字。
- 每条提醒都应说明来源、时间或原因。
- 娱乐模块不显示类似“逾期”的压力型提醒。

## 6. 本地数据文件、备份和恢复要求

### 6.1 本地数据文件

- 业务数据必须保存在当前电脑上的独立文件中，不能只依赖浏览器的 Local Storage、Session Storage 或 IndexedDB。
- 第一版优先采用单个 SQLite 数据库文件作为主要数据文件；如果开发阶段调整技术方案，仍必须满足独立文件、可定位、可复制和可完整恢复的产品要求。
- 用户需要能够在“数据与设置”中看到数据文件的完整位置、文件大小和最近修改时间。
- 本地服务只能监听本机回环地址，不允许同一网络中的其他设备直接访问。
- 每次写入需要明确成功或失败；写入失败时不得显示“已保存”。
- 刷新页面、关闭浏览器、关闭本地服务和重启电脑后，已成功保存的数据必须保留。

### 6.2 手动备份

- 用户可以随时创建包含全部业务数据和设置的完整备份。
- 备份必须是电脑上的独立文件，不能只在主数据文件内部做标记。
- 备份列表需要显示创建时间、文件大小、类型和备注。
- 用户可以给重要备份命名或标记为长期保留。

### 6.3 自动备份

- App 每天至少自动备份一次；如果当天已经存在有效自动备份，则不必重复创建。
- 默认保留最近 30 份普通自动备份。
- 被标记为长期保留的备份不能被自动清理。
- 自动备份失败时，首页或顶部工具栏需要明确提示。

### 6.4 恢复

- 恢复前必须显示目标备份的时间、大小和备注，并要求用户确认。
- 覆盖当前数据前，系统必须先自动创建一份当前状态的安全备份。
- 恢复前应检查备份是否可读取且结构有效；无效备份不得覆盖当前数据。
- 恢复成功后，所有页面需要重新加载恢复后的数据，并明确提示成功。
- 恢复失败时应保留当前数据，并给出可理解的错误提示。

### 6.5 导出

- 第一版需要提供面向迁移和人工查看的常见格式导出。
- 导出至少应覆盖所有核心业务记录；具体采用 JSON、CSV 或压缩包由开发设计决定。
- 导出不替代完整备份，界面上需要区分“备份”和“导出”。

## 7. 第一版必须完成的功能

1. 完成九个主要页面及左侧分组导航。
2. 完成统一顶部工具栏、全局搜索、快速新增和保存状态提示。
3. 完成首页的今日概况、时间线、待安排事项、快速备忘、需要关注和模块摘要。
4. 完成今日计划的今日、本周和历史视图，以及新增、编辑、完成、取消和延期操作。
5. 支持今日计划与各业务模块记录之间的关联和跳转。
6. 完成自媒体的内容制作流程、发布计划和基础数据记录。
7. 完成开发工作的项目、里程碑、工作项和开发日志管理。
8. 完成咨询工作的客户、项目、沟通、交付、跟进、时长和简单费用记录。
9. 完成健身计划、实际训练、动作组数、身体数据和简单趋势展示。
10. 完成饮食计划、实际摄入、常用食物、营养目标和当天汇总。
11. 完成游戏娱乐清单、进度、游玩记录、下一次目标和累计时间。
12. 完成本地独立数据文件的持久化。
13. 完成手动备份、每日自动备份、备份列表和安全恢复。
14. 完成核心数据导出。
15. 完成回收站、删除确认和必要的撤销操作。
16. 完成主题、日期格式、每周起始日和首页摘要等基础设置。
17. 为主要页面和操作提供空数据、加载中、成功和出错状态。

## 8. 第一版暂时不做的功能

- 用户注册、登录和多用户权限。
- 云同步、云数据库或多设备同步。
- 公网部署和局域网共享。
- 手机 App 或专门的移动端适配。
- 微信、抖音、B站等自媒体平台的数据自动同步。
- 自动抓取发布后的播放、阅读或互动数据。
- GitHub、日历、邮箱及其他第三方服务集成。
- AI 自动规划、自动写文案、自动总结或智能营养识别。
- 完整的 CRM、财务、开票、合同或会计系统。
- 可穿戴设备、健身平台和健康平台同步。
- 在线食物营养数据库和扫码识别。
- 多人协作、审批、消息推送和共享。
- 复杂的数据分析、自定义仪表盘和自定义报表。
- 跨浏览器全面兼容保证；第一版只需在明确选定的一款桌面浏览器中完整通过验收。

## 9. 可以实际检查的验收标准

以下标准均应能够通过界面操作、文件检查或明确的测试步骤验证。

### 9.1 运行和访问

- `AC-001`：在目标电脑启动本地 App 后，可以通过目标桌面浏览器打开首页，无需联网和登录。
- `AC-002`：断开互联网后，除明确标记为外部链接的内容外，全部第一版核心功能仍可使用。
- `AC-003`：从同一局域网中的另一台设备无法直接访问该 App。
- `AC-004`：左侧导航能够进入全部九个主要页面，页面名称和分组与本 PRD 一致。

### 9.2 数据持久化

- `AC-005`：分别在今日计划和七个业务模块中创建一条记录后刷新页面，所有记录仍然存在。
- `AC-006`：关闭浏览器并重新打开 App 后，之前已保存的数据仍然存在。
- `AC-007`：关闭本地 App 服务并重新启动后，之前已保存的数据仍然存在。
- `AC-008`：重启电脑并重新启动 App 后，之前已保存的数据仍然存在。
- `AC-009`：在“数据与设置”中可以看到主数据文件的完整路径、大小和最近修改时间，并能在电脑文件系统中找到该文件。
- `AC-010`：人为制造不可写条件后再编辑记录，界面应显示保存失败，不得错误显示为已保存。
- `AC-040`：顶部始终提供“手动保存”按钮；点击后当前快速备忘或当日复盘草稿立即提交，数据库完成磁盘检查点和完整性检查，重新打开后数据仍存在。

### 9.3 首页和模块联动

- `AC-011`：创建属于今天且设置具体时间的事项后，该事项出现在首页时间线中。
- `AC-012`：创建属于今天但没有具体时间的事项后，该事项出现在首页待安排区域。
- `AC-013`：在首页或今日计划中标记事项完成后，两处的状态和今日完成进度同时更新。
- `AC-014`：从任一业务模块把一条行动加入今日计划后，今日计划中出现关联项，且可以返回原始记录。
- `AC-015`：修改原始业务记录的标题后，首页和今日计划中显示的新标题保持一致，不产生重复业务记录。
- `AC-016`：点击首页模块摘要，可以进入对应模块或打开对应记录。
- `AC-017`：快速备忘输入后刷新页面仍然存在，并可以成功转换为今日事项或指定模块记录。

### 9.4 各模块的场景能力

- `AC-018`：今日计划可以设置日期、时间、预计时长和优先级，并可以完成、取消和延期。
- `AC-019`：自媒体内容可以在五个制作阶段之间移动，发布后可以记录链接和基础表现数据。
- `AC-020`：开发工作可以建立项目和里程碑，并分别记录功能、需求、Bug、技术问题及开发日志。
- `AC-021`：咨询工作可以建立客户和项目，并记录沟通、交付物、跟进时间、咨询时长和可选费用。
- `AC-022`：健身模块可以从模板开始一次训练，逐组记录实际次数和重量，并查看上一次同动作数据。
- `AC-023`：饮食模块可以分别保存计划餐食和实际摄入，并按已填写数据汇总当日热量和蛋白质。
- `AC-024`：游戏娱乐模块可以维护想玩、正在进行、暂停和已完成状态，并记录一次游玩时长和下一次目标。
- `AC-025`：各模块的上述专属信息都能保存和重新读取，不能仅表现为相同字段的通用任务列表。

### 9.5 搜索、删除和设置

- `AC-026`：全局搜索能够搜索至少七个业务模块中的核心记录，并按模块展示结果。
- `AC-027`：删除一条记录后，该记录进入回收站；从回收站恢复后，记录及其核心内容重新出现。
- `AC-028`：永久删除前必须再次确认，取消确认不会删除记录。
- `AC-029`：修改主题、每周起始日、日期格式或首页摘要设置后刷新页面，设置仍然生效。
- `AC-030`：没有任何数据的模块会显示与该模块有关的空状态和新增入口，而不是空白页面或报错。

### 9.6 备份和恢复

- `AC-031`：点击“立即备份”后，电脑备份目录中生成新的独立备份文件，列表显示正确的时间和大小。
- `AC-032`：为备份添加名称或长期保留标记后，刷新页面仍能看到该信息。
- `AC-033`：当天不存在自动备份时启动 App，系统能够创建一份自动备份；当天已经存在有效自动备份时不会无限重复创建。
- `AC-034`：普通自动备份超过 30 份时可以按规则清理旧备份，被标记长期保留的备份不会被清理。
- `AC-035`：创建备份后修改或删除数据，再恢复该备份，数据应回到备份创建时的状态。
- `AC-036`：执行恢复前，系统会额外生成一份当前数据的安全备份。
- `AC-037`：尝试恢复无效或损坏的备份时，系统拒绝覆盖当前数据并显示明确错误。
- `AC-038`：模拟备份写入失败时，顶部工具栏或首页显示备份失败状态。
- `AC-039`：执行核心数据导出后，可以在导出文件中找到各模块记录；导出操作不会修改主数据。

## 10. 第一版完成定义

只有在以下条件全部满足时，第一版才视为完成：

1. 第 7 节列出的必须完成功能已经实现。
2. 第 9 节验收标准全部通过，或存在经过用户明确接受并记录的例外。
3. 没有会导致已保存数据丢失、错误覆盖或无法恢复的已知严重问题。
4. 用户能够在不阅读源代码的情况下完成启动、日常使用、备份和恢复。
5. 实际实现没有擅自加入第一版明确暂不处理的联网、登录、云服务或多用户依赖。
